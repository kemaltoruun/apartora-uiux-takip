## 1. Yöntem: derin incele, az kullan

Sahip cümlesi iki işe ayrıldı:

1. Olgun ürünleri **GitHub projesi gibi** oku (kaynak, kural, anti-örnek).
2. Apartora’ya **yalnız ihtiyaç olanı** taşı.

Karşılaştırılan üç olgun kabuk:

| Ürün | Kullanıcının zihinsel modeli | Birincil nesneler | Bize uyar mı |
|---|---|---|---|
| **GitHub** | “Bu repo’da iş yapıyorum” | Code · Issues · PRs · Settings | **Bağlam + geçiş kuralları evet**; 9 sekme hayır |
| **Shopify admin** | “Bu dükkânda iş yapıyorum” | Home · Products · Orders · Settings | **Frame (kabuk/gövde) evet**; App Bridge hayır |
| **Stripe Dashboard** | “Bu hesabın parası” | Payments · Customers · Products | **Nesne-önce evet**; tam kopya hayır |

Apartora kullanıcısının modeli: **“Bu sitede (binada) para ve insan işi yapıyorum.”**  
GitHub’daki repo = bizim **site**. Stripe’daki Payments = bizim **Aidat**. Shopify’daki Orders = bizim **Talepler** (iş kuyruğu).

## 3. Primer’den alınan geçiş sözlüğü (çekirdek)

Primer Navigation (2026, canlı kılavuz) **altı geçiş tipi** tanımlar. Karıştırmayı açıkça yasaklar: URL değiştiren sekme ile yalnız panel değiştiren sekme **aynı çubukta olamaz**.

| Tip | Primer adı | URL | Apartora örneği (şimdi) | Olması gereken |
|---|---|---|---|---|
| T1 | Entirely new page | değişir | Özet → Aidat (sekme) | Kabuk kalır; geri = diğer sekme (stack değil) |
| T2 | Same page, different state | değişebilir | Aidat çipleri (Bekleyen / Tümü) | **UnderlinePanels** davranışı: aynı iş, URL opsiyonel `?tab=` |
| T3 | New spot on same page | çapa olabilir | Özet’te Mali Durum’a kaydır | Bölüm başlığı; tam sayfa değil |
| T4 | Moving into a Dialog | değişebilir | Toplu tahsilat, Hatırlat | Para/onay işi; arkasındaki liste **kaybolmaz** |
| T5 | Parent → child page | değişir | Liste → daire/aidat detayı | Geri = ebeveyn. Primer: dar ekranda sidebar kaybolur, **geri zorunlu** |
| T6 | Overflow (ActionMenu / bottom sheet) | değişebilir | Web “Daha” · mobil Menü · ⋯ | ≤15 madde menü; fazlası sheet. Nav değil, **taşma** |

**Nav ≠ Action (Primer NavList vs ActionList):**

- NavList öğesi **link’tir**, URL değiştirir.
- ActionList / ActionMenu **iş’tir** (sil, dışa aktar, tema).
- Şimdi sapma: sidebar’da “Banka Hesap Entegrasyonu” düğme (dosya 4) — bu **action**. Tema/Dil/Çıkış da action. Bunlar NavList gibi dizilirse koku bozulur.

**PageHeader kuralı (Primer + Polaris aynı):** Ana gövdenin üstü = “neredeyim” + birincil eylem. Dilim 1’deki site adı / dönem bu kuralın Apartora hali; yeni başlık sistemi uydurulmaz (`DashboardHeader` / `PageHeader` kanonik).

## 4. GitHub eşlemesi — alınan / alınmayan

GitHub’un gerçek IA’sı: **kalıcı bağlam (org/repo) + az sayıda birincil görünüm + Settings taşması.**

| GitHub | Apartora karşılığı | Al / alma |
|---|---|---|
| Repo adı her zaman görünür | Site adı her sekmede | **AL** (Dilim 1 V1; hâlâ RISK — dosya 20) |
| Code (nesnenin evi) | Özet | **AL** anlam olarak; “Ana Sayfa”/“Özet” tek ad (P7 sözlük) |
| Issues | Talepler | **AL** |
| Pull requests (günlük iş kuyruğu) | Aidat | **AL** (para kuyruğu) |
| Contributors / People | Kişiler | **AL** |
| Settings | Menü + Hesabım + Site Yönetimi | **AL** taşma olarak |
| Actions · Projects · Wiki · Security · Insights | — | **ALMA** — güç kullanıcısı yüzeyi; yönetici günlük işi değil |
| ⌘K komut paleti | global arama zaten var (dosya 3) | **ALMA** (şimdi). Arama yeter |
| Primer React / Primer CSS / `@primer/primitives` | kendi token + shadcn | **ALMA** paket. Ortak token **kararı** zaten borç (coding-patterns §7) — Primer boru hattını kopyalamayız |
| 8–9 UnderlineNav | 5 sekme | **ALMA** sayı. Hick |

`primer/primitives` incelendi: Style Dictionary benzeri çok katmanlı token (base → functional → component). Apartora’nın ihtiyacı **L0–L5 semantik** (dosya 4); primitives’in derleme zinciri web+RN üç hedefe maliyet. **Şimdi alma.**

## 5. Polaris / Stripe — yalnız birer kural

**Shopify Frame:** uygulama = TopBar (arama · kullanıcı) + Nav + Body. Mobilde nav title-bar dropdown olur; masaüstünde sol. Apartora’da bu **zaten var** (web sidebar · mobil alt sekme). Alınacak: “Home `rel=home` menüde tekrar etmez” — Özet hem logo hem 1. sekme ise çift ev kokusu. Şimdi: web “Ana Sayfa” + mobil “Özet” (dil çifti, dosya 18 M4).

**Polaris IA:** birden fazla yol bulma şeması (yapısal nav + arama + breadcrumb + avatar). Bunu alıyoruz; tek ağaca her şeyi tıkamayız.

**Stripe:** sayfada **tek solid birincil**. Bu, KARAR K14 adayı ile aynı; mimari kural olarak burada da durur. Hex değil.

## 6. Kullanım mimarisi (Apartora’ya sığdırılmış)

Dört katman. Üsttekini bozmadan altını değiştir.

```
K0  Kimlik kabuğu     site · rol · bildirim · avatar   (GitHub repo bar)
K1  Alışkanlık nav    Özet | Aidat | Kişiler | Talepler | Menü
K2  İş yüzeyi         liste / pano / form   (gövde)
K3  Nesne + eylem     bir daire, bir aidat, bir talep + birincil fiil
```

**Günlük nesneler (Hick kesimi):**

| Nesne | Yönetici işi | Sakin işi | Nav yeri |
|---|---|---|---|
| Site | hangisindeyim | hangisindeyim | K0 (değiştirici, nav değil) |
| Para (Aidat) | tahsil / hatırlat | öde | K1 2. sekme |
| Kişi | kim oturuyor | — | K1 3. sekme |
| İş (Talep) | kuyruk | talebim | K1 4. sekme |
| Geri kalan | bakım, evrak, güvenlik, finans çatı | belgeler | K1 5. Menü |

Web sidebar 8 grubu **silinmez**. Tavsiye (sonra, oy + sahip): grup başlıklarını nesneye hizala (Para · Kişiler · İş · Site · Güvenlik) ve sakin yollarını K0 rol geçişine taşı (dosya 20 P1). Bu turda ağaç yeniden çizilmedi.

**Derinlik:** günlük iş ≤2 dokunuş (dosya 5 §2.4). T5 (detay) üçüncü; T4 (diyalog) sayılmaz çünkü kabuk durur.
